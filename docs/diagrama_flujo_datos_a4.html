🔄 ElectroFrío V2 — Diagrama de Flujo de Datos (DFD)

EF DFD

MAPA DE FLUJO Y CONEXIÓN DE DATOS EN TIEMPO REAL

Traza de extremo a extremo: Desde el contacto del cliente hasta la ejecución en campo y la caja

Modelo: Data Flow Diagram (DFD Nivel 1)
Base de Datos: Firestore Reactivo (onSnapshot)
Formato: Hoja A4 Paisaje (1 carilla)
Etapa 1 • Comercial

Contacto y Presupuesto

Captación de cliente, cotización de repuestos y mano de obra.

Etapa 2 • Despacho

Orden de Trabajo (OT)

Coordinación de horario, domicilio y asignación de técnicos.

Etapa 3 • Campo

Planilla Digital (PDT)

Geolocalización, reporte técnico y consumo de repuestos.

Etapa 4 • Tesorería

Liquidación y Cobro

Impacto en cuenta corriente, cargos, cobros y saldo cliente.

1. Proceso Comercial D1 / D4
⚙️ P1. Cotizar Servicio
Consulta precios en almacenes de catálogo y formula propuesta.
📥 In: materiales + mano_obra
📤 Out: presupuestos ➔ PDF / WhatsApp
📁 D1: clientes PK: id
Nombre / Razón Social: name
Teléfono y Domicilio: phone, address
Multi-direcciones: addresses[]
Saldo Cuenta Corriente: balance ($)
Fase Embudo: pipelineStage
📁 D4: presupuestos PK: id
Cliente Vinculado: client.id (FK)
Número Presupuesto: number
Artículos y Labores: items[] (mat & mo)
Subtotal, Bonif, Total: total ($)
Estado: status (Aprob/Rech)
2. Planificación OT D5 / D8
⚙️ P2. Programar y Despachar
Crea la OT a partir del cliente o presupuesto aprobado y asigna al equipo.
📥 In: clientes.id + usuarios
📤 Out: ordenes ➔ Calendario & Mapa
📁 D5: ordenes PK: OT-XXXX
Cliente Vinculado: clientId (FK D1)
Nombre / Dirección Caché: client, address
Técnicos Asignados: assignees[] (FK D8)
Fecha y Franja: date, timeRange
Estado de Ejecución: status (Pend/En Curso)
Tipo de Trabajo: type, observations
📁 D8: usuarios (Colaboradores) PK: uid
Nombre y Usuario: name, username
Rol de Acceso: role (Admin/Colab)
Presencia en Vivo: status (online/off)
Color Calendario: color (#hex)
3. Ejecución Técnica D6 / D9
⚙️ P3. Registrar Labor y Cierre
Técnico ficha con GPS, ejecuta el servicio y completa el informe digital PDT.
📥 In: ordenes.id + GPS + insumos
📤 Out: planillas ➔ Cierra OT
📁 D6: planillas (PDT Digital) PK: id
Orden Asociada: orderId (FK 1:1 D5)
Código PDT: pdtCode (PDT-XXXX)
Cliente Vinculado: clientId (FK D1)
Horarios de Servicio: horaEntrada, horaSalida
Técnicos Presentes: technicians[], completedBy
Repuestos e Insumos: spareParts (➔ D2)
Mano de Obra Aplicada: manoObra (➔ D3)
Resultado: estadoPDT (REALIZADO)
📁 D9: fichajes (Control Horario) PK: id
Técnico Responsable: username (FK D8)
Fecha y Hora: date, time, timestamp
Tipo de Marca: type (Entrada/Salida)
Geolocalización: gps: {lat, lng, verif}
4. Finanzas y Cobros D7 / D2-D3
⚙️ P4. Liquidar y Cobrar
Carga el débito por el servicio realizado y registra cobros en efectivo o transferencias.
📥 In: planillas.pdtCode + importe
📤 Out: cobros_mov ➔ Actualiza Saldo
📁 D7: cobros_movimientos PK: id
Cliente Imputado: clientId (FK D1)
Tipo Movimiento: type ('cargo' | 'abono')
Monto Monetario: amount ($)
Medio de Pago: paymentMethod
Concepto / Comprobante: concept, receiptNumber
Fecha Transacción: date, createdAt
📁 D2-D3: Catálogo Almacén materiales / mano_obra
Materiales: codigo, stock, costo, venta
Mano de Obra: codigo, labor, tarifa, minutos
Propósito: Estandariza costos en P1 y P3

🔁 Conexión de Datos y Dependencias del Sistema

Flujo de Datos Origen Destino Datos que Viajan Acción que Dispara
1. Aprobación Presupuesto presupuestos ordenes clientId, clientName, items Apertura automática de Orden de Trabajo.
2. Asignación Logística usuarios ordenes assignees[] (uids / nombres) Aparece en la agenda del técnico en tiempo real.
3. Cierre de Planilla planillas ordenes orderId, estadoPDT Cambia estado de la OT a "Completado".
4. Imputación de Cuenta cobros_movimientos clientes amount, type (cargo/abono) Suma o resta directamente al balance del cliente.

📌 Claves de Conexión

  • D1 (Clientes) es el centro gravitacional: todo presupuesto, orden y movimiento financiero conecta con un clientId.
  • D5 ➔ D6 (1 a 1): Una OT origina una única PDT con el detalle real de insumos usados.
  • Sincronización Reactiva: Todo cambio en Firestore actualiza instantáneamente las pantallas de Oficina y los teléfonos de los Técnicos sin recargar la página.
